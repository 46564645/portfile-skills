# Project Types

Use for specialized portfolio strategies by project type: interaction/UX, HCI, industrial design, social issue, technical system, game, service, coursework-upgrade, and top-school applications.

## Source Coverage

From Tip items 03, 05, 08, 09, 10, 11, 19, 20, 21, 22, 23, 24, 25, and 26.

## Interaction / UX Projects

Recommended flow:

1. Topic or problem selection.
2. Research: interviews, questionnaires, observation, competitor analysis.
3. Need analysis: user pain points, task flow, user journey, information architecture.
4. Concept design: sketches, flow diagrams, low/high fidelity prototypes, design decision reasons.
5. Validation and iteration: usability test, feedback, before/after improvement.
6. Final presentation: core flow, key interactions, visual highlights, scenario, and problem closure.

Warnings:

- Do not stack UI screenshots without explaining interaction logic.
- Do not show research as raw text; turn it into insights and diagrams.
- Show at least three rounds of refine/iteration when the source context supports it.

## HCI / Human-Computer Interaction Projects

HCI portfolios benefit from showing both frontier awareness and feasible interaction logic.

Potential directions from item 23 include:

- non-contact gesture recognition and mid-air haptics,
- VR/AR tactile tools,
- sound-touch interaction,
- air vortex or ultrasound remote haptics,
- emotion-sensing facial patches,
- paper-to-XR interaction,
- wearable environmental sensing,
- XR plus generative AI,
- 3D remote presence,
- immersive spatial drawing.

Presentation strategy:

- Explain what human ability, body sense, context, or system is being redesigned.
- Show technical principle, interaction flow, prototype, user scenario, and feasibility evidence.
- Avoid only showing futuristic references. Connect technology back to human need.

## Industrial / Technical System Projects

For technical or industrial projects, layout must prove credibility:

- Decompose abstract concept and physical realization.
- Use a logic sequence such as concept definition -> gesture/system definition -> technical implementation/product making.
- When showing sensors, robots, mechanisms, materials, or prototypes, switch to high-contrast detail images, engineering diagrams, mechanism illustrations, and data support.
- Include process proof: mechanism diagram, flow proof, data support, detail close-up.

If the project has a prototype, include Proof of Concept close-ups.

## Social Issue / Service Projects

For social issue pages, avoid a "news report" look caused by colorful photos and scattered data.

Use layered academic structure:

- Macro data layer: statistics, policies, background.
- Case/person layer: persona, interview, empathy map.
- Analysis layer: problem tree, insight map, service gap.
- Design layer: blueprint, UI/service, intervention, scenario.

Color strategy:

- Use grayscale or black/white photography for restraint.
- Add one meaningful accent color to mark sensitive or important information.
- Balance empathy with academic order: large portraits can hold narrative tension, but keep them in a grid with concise quote highlights.

## Game / Interactive Installation Projects

From item 19:

- Show title, cover, background, core concept, theme, player, references, game purpose.
- Explain core loop, basic controls, rules, interaction, map, levels, pass/fail conditions, onboarding, collectables, and obstacles.
- Show production: art, characters, programming, engine implementation, workflow, prototype or playtest.
- End with player operation, full-flow map, demo, test feedback, future development, release or packaging evidence.

Prioritize mechanics and readable player experience, not only atmosphere images.

## Top-School Review Criteria

From item 11 and 24:

- **Information clarity**: reviewers must quickly understand the project core.
- **Cross-disciplinary integration**: show how different knowledge areas connect rather than sit apart.
- **User experience and interaction**: show how users engage with the design, not only static objects.
- **Research proposition**: the question should be original, grounded, and connected to real need.
- **Design analysis**: use analysis tools to transform information into design opportunity.
- **Team ability**: when relevant, clarify personal role, collaboration, conflict resolution, and reflection.
- **Storytelling**: connect discovery, design process, and final output in one narrative.

## Portfolio Structure and Project Count

From item 20 and 21:

- Common full portfolio structure: cover, resume/profile, table of contents, 3-5 core projects, other works, end/contact page.
- Four projects is often a safe interaction portfolio number, but always follow target school requirements.
- Put the strongest and most relevant project first.
- Use project order to form a designer image: theme continuity, ability progression, or emotional/intellectual arc.

## Personal Mainline and Social Value

From item 25:

- A strong portfolio often has a clear mainline across projects.
- Social公益 topics can show empathy and responsibility when handled rigorously.
- Technology should serve need, not replace design thinking.
- AI can improve efficiency, but the portfolio still needs the designer's own concept, emotion, and judgment.

## Systematic and Narrative Interaction Thinking

From item 26:

- **Systematic design**: show ecosystem consistency, task flow, information architecture, hardware/software relation, and online/offline service structure.
- **Narrative experience**: show what feeling or story the design creates through space, touchpoints, roles, and immersion.
- Strong projects combine functional, commercial, and social value.
