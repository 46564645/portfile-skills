# Common Problems

Use for diagnosis checklists, text-heavy pages, unclear hierarchy, structural imbalance, disconnected images/text, and common portfolio review risks.

## Source Coverage

From Tip items 02, 14, 16, 17, 19, 20, 21, 22, and 24.

## High-Risk Structural Problems

### 1. Structure Imbalance

Symptom:

- The portfolio reads like a paper rather than a design portfolio.
- Research occupies too many pages while development and final result are weak.

Fix:

- Compress early research into Key Insights.
- Make Development/Deliver occupy about 60% or more when the project needs to prove design ability.
- Replace raw research paragraphs with maps, diagrams, and summarized conclusions.

### 2. Flat Information Hierarchy

Symptom:

- Titles, body, captions, images, and charts compete at similar visual weight.
- Reviewers cannot identify the page's core quickly. Source item 16 specifically mentions 5 seconds for title/main visual logic and 10 seconds for catching the key point.

Fix:

- Enlarge the main title or key statement.
- Create a clear main visual.
- Reduce supporting text and convert secondary content into labels, captions, or diagrams.
- Use size, weight, color, position, and spacing differences.
- Do not prescribe a made-up title/body ratio; say to拉开层级 unless a source number exists.

### 3. Missing Implementation Detail

Symptom:

- The final idea looks attractive but unproven.
- Prototypes or technical mechanisms are only shown as final renderings.

Fix:

- Add Proof of Concept close-ups.
- Show mechanism diagrams, technical details, testing evidence, user feedback, before/after iteration, and material/process shots.

## Three Common Narrative Pain Points

From item 02:

- **内容逻辑断裂**: The page has content but no clear relationship. Fix by placing raw text first, identifying cause-effect, sequence, or comparison, then editing.
- **图文割裂**: Images and text sit independently. Fix by making visuals according to the written meaning and connecting them with lines, captions, scale, or placement.
- **叙事混乱**: The page lacks priority. Fix by using visual hierarchy and page micro-adjustments to reinforce main/sub relationship.

## Text-Heavy Pages

Symptoms:

- Paragraphs dominate the page.
- The user wants to "say everything".
- The reviewer cannot locate the insight.

Fix:

- Keep only key innovation, insight, decision, or conclusion.
- Split text into labels, short bullets, quotes, or diagram annotations.
- Convert repeated explanation into visual evidence.
- Use one strong sentence as page anchor, then support with images/charts.

## Visual Disconnection

Symptoms:

- Two blocks are placed side by side but no relationship is visible.
- Images are decorative rather than explanatory.
- The page looks like a material board.

Fix:

- Clarify whether blocks are cause/result, before/after, problem/solution, evidence/conclusion, or user/system.
- Add linking lines, arrows, comparison labels, or shared color coding.
- Enlarge the more important block and reduce the supporting block.

## Over-Symmetry and Fragmentation

Symptoms:

- The page is split exactly in half.
- Too many equally small blocks appear.
- The page feels too balanced but has no focus.

Fix:

- Use 1/3 and 2/3 division.
- Merge small blocks into groups.
- Create a main visual or key statement.
- Reduce decorative fragments.

## Color and Style Problems

Symptoms:

- Pages feel unrelated to each other.
- Colors are noisy or dull.
- Everything competes for attention.

Fix:

- Define one project color system.
- Use repeated visual language across pages: circles, outlines, lines, local highlights, or image treatment.
- Weaken backgrounds and secondary images.
- Use accent color only where attention is needed.

## Interaction Portfolio Problems

Symptoms:

- The project shows methods but no design opportunity.
- UI screens appear without explaining user need or task flow.
- Iteration and testing are missing.

Fix:

- Show topic -> research -> need -> concept -> prototype -> validation -> final.
- Use user journey, task flow, information architecture, and testing comparison.
- Include reflection or next-step thinking when it reveals design maturity.

## Application Positioning Problems

Symptoms:

- Project order does not match target school or reviewer.
- The portfolio lacks a designer identity.
- It tries to show every skill equally and becomes unfocused.

Fix:

- Identify the target reader first.
- Put the strongest and most relevant project first.
- Build a mainline through theme, user group, technology, social concern, or design attitude.
- Use other works only to supplement, not distract from the core profile.
