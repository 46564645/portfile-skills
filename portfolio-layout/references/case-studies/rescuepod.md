## 0. Format and Global Visual System

- **Format**: 11 landscape spreads, 1684 × 595 (about 2.83:1). Reading runs left to right, usually in two or three zones.
- **Project type**: wearable sensing device (hardware + firmware + ergonomics), worn on the shin of flood responders.
- **Narrative voice**: first person singular, "I".
- **Background**: dark brown, muddy-water textured pages, with white rounded cards for dense data. Key comparison areas use bright mustard-yellow backgrounds (the V2 half of page 08, for example).
- **Accent**: mustard/amber yellow, for section titles, highlighted keywords, Conclusion/Feedback bars and the "improvement" side. Dark brown marks the "problem" side.
- **Functional colour code**, kept on every page from 03 to 11 in icons, LEDs, test frames and alert cards: **red = Drop, blue = Flow, yellow = Obstacles**.
- **Section titles**: spaced all-caps sans in yellow or white (e.g. "BACKGROUND", "V1 SHELL WEAR TEST"). Page-level questions are set in bold italic (e.g. "Where exactly is it most dangerous in a rescue?").
- **Recurring components**: dark/yellow conclusion bars at the bottom of each column; numbered cards; "Insight" tags beside quotes; ✗/✓ sketches; Issue/Conclusion rows; "To verify…" test blocks; score cards.
- **Naming inconsistency** (weakness): the product appears as "RescuePod" (cover title), "Eddyline" (cover body) and "EddyLine" (page 11).

## 2. Detailed Logic Chain

## 4. Strengths, Weaknesses, Transferable Lessons

**Why it works**
1. A funnel that ends in measurable variables: flood → responders → last 100 m → Dark Water → three physical quantities.
2. One "three" runs through everything: risks, sensors, colours, vibrations, tests, alert cards.
3. Form is derived by elimination from body constraints.
4. A transparent, reproducible making chain: paper Ver.001–003 → exploded view → 6-step assembly → 6 waterproofing steps → V1 → V2.
5. Layered validation: single-factor → multi-factor priority → real river → scored usability.
6. An honest low score, linked to the next iteration.
7. The colour code doubles as product semantics: alert colours on the device are the same as the layout categories.

**Weaknesses to avoid**: three names for one product; repeated interview intro and photos (02/03); n = 1 described in the plural; thresholds and statistics without sources; overloaded page 02; typos (mash, a inner, WEAR ABILITY, townships.It); a final page that does not answer the opening question; no competitor page; the field tester is not one of the interviewees.

**Transferable lessons**
- Narrow research level by level (macro → group → scene → measurable variables) and hand over each level with a conclusion bar.
- Give the core problem a memorable name and a colour/icon set, and reuse them to the last page.
- Map each variable → module → feedback → test → final-page element.
- Derive placement or form by elimination ("constraint: fact, so…").
- Write iteration as Issue → Conclusion bands; name V1 problems and V2 fixes as mirrors.
- State method + threshold + output, and cite where each threshold comes from.
- Follow single-factor tests with a multi-factor or edge test.
- Report score scale and sample size, highlight the lowest score, and don't pluralise n = 1.
