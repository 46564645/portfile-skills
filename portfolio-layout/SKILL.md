# Portfolio Layout

## Overview

Use this skill to help design students diagnose and improve portfolio layout quality. It supports two modes: diagnosing uploaded portfolio pages and teaching layout principles for portfolio planning, narrative, visual hierarchy, and project-type presentation. Give concrete recommendations; create charts or edit portfolio pages only when separately requested. The portfolio pages are in English: suggested headings, chart titles, labels, captions, and replacement copy should be in English even when the explanation to the user is in Chinese. Do not include palette or colour-matching advice.

Keep advice concrete, page-specific when images are provided, and grounded in the reference knowledge. Do not give only aesthetic opinions; connect every suggestion to clearer reading, stronger logic, or better professional evidence.

## First Layout Principle: Reveal Relationships and Data

Before typography, spacing, or decorative treatment, check whether the page needs to show a relationship or data comparison. “Relationship” is broad: it may connect items inside one module, a photograph to its caption, observations to themes, evidence to a claim, research to a design decision, people to touchpoints, parts to a whole, or events across time or space. If a visual form would make the relationship clearer, recommend the appropriate chart, diagram, table, annotated sequence, or spatial alignment. Do not force a chart where a short sentence or simple side-by-side layout is clearer. Read `references/visualization.md` for the decision process, then its linked atlas or cases only as needed.

## Numeric Integrity

Do not invent exact numeric prescriptions. Only give concrete numbers, ratios, page counts, time thresholds, spacing units, or percentages when they appear in the source references, such as 4/8 spacing multiples, 15mm margins, 1920 x 1080, 1/3 and 2/3 page division, 60% Development/Deliver weight, or source-stated scan times/page counts. If the source does not provide a number, use qualitative guidance such as "拉开字号层级", "增加主次对比", "压缩正文", "扩大主视觉", or "统一间距".

## Case Evidence Integrity

When using external优秀案例, 小红书案例, screenshots, or scraped case folders, treat them as visual examples, not authoritative rules. Do not store copyrighted source images in the skill. Use text files only as weak context for title, project type, and keywords; ignore marketing copy unless it states observable project/page facts. Only describe what can be seen in the image or explicitly read in the text. Do not invent project background, design intent, school outcome, author identity, or detailed concept if the case files do not state it.

## Diagnosis Workflow

When the user uploads portfolio pages or asks for review, inspect in this order:

1. **关系与数据**: Identify what the reader must compare, follow, or connect, including relationships within a module. If the relation is hidden in prose or scattered evidence, suggest a fitting chart, diagram, table, or spatial arrangement and explain why.
2. **逻辑骨架**: Check whether the page has a clear narrative path such as WHY -> HOW -> WHAT, Inspiration -> Research -> Development -> Final, or background/problem -> method -> solution.
3. **信息层级**: Check whether project title, section title, key insight, body text, labels, captions, and images have clear size/weight/position differences.
4. **间距系统**: Check whether spacing, alignment, page margins, and blocks feel unified. Prefer 4/8 multiples for digital layout unless expressive collage requires exceptions.
5. **视觉对比**: Check size, density, straight/curved forms, text/image balance, and whether there is a clear visual focus.
6. **结构比例**: Check whether research has been compressed into key insights and whether Development/Deliver carries at least about 60% of the project weight when appropriate.
7. **落地细节**: Check whether prototypes, mechanisms, tests, Proof of Concept details, interaction flows, or implementation evidence are shown close enough to prove feasibility.

For each finding, provide:

`位置/页面 + 问题描述 + 为什么影响阅读或申请判断 + 具体改法`

Example format:

`第2页：标题与正文差异太小，信息层级过平，老师很难快速抓到重点。建议明显拉开主标题、关键结论和正文的字号/字重差异，把关键结论单独做成高亮句，并压缩正文，只保留必要信息。`

If image quality is low or the page cannot be read, state what can be judged visually and what needs a clearer crop.

## Teaching Workflow

When the user asks a principle or "how to layout X" question, first identify the knowledge module, then read only the relevant reference file:

| User intent | Read |
|---|---|
| Spacing, alignment, margins, paragraph, page size | `references/basic-rules.md` |
| Narrative order, project logic, story structure, transforming coursework into projects | `references/logic-framework.md` |
| Visual hierarchy, contrast, balance, information density, three-column layout | `references/visual-principles.md` |
| Diagrams, measured data, broad visual relationships, collage, image/evidence arrangement, visual research pages | `references/visualization.md`; follow its links to `relationship-layout.md`, `chart-selection.md`, or `visualization-case-studies.md` only as needed |
| Interaction, UX, HCI, industrial design, social issue, technical, game, service, top-school strategies | `references/project-types.md` |
| Common layout mistakes, diagnosis checklists, text-heavy pages, structure imbalance | `references/common-problems.md` |
| Analyzing excellent portfolio examples or scraped case folders | `references/case-analysis-method.md` |
| Looking for reusable layout pattern names after case extraction | `references/case-patterns.md` |

Answer teaching questions with:

1. A direct principle.
2. A concrete layout method.
3. A small example based on the reference cases when relevant.
4. A short checklist the user can apply to their own page.

## Case Library Workflow

When the user provides a folder of优秀案例:

1. Read `references/case-analysis-method.md`.
2. For each case folder, pair images with any local txt file, but filter titles, tags, and marketing language from layout evidence.
3. Record only observable layout features: page type, structure, hierarchy, image/text relationship, color strategy, visual focus, reading path, and reusable pattern.
4. Save distilled patterns in `references/case-patterns.md` only after actual case review. Mark unverified patterns as hypotheses or omit them.
5. In future diagnosis, recommend a pattern as a direction, not as a rule to copy.

## Professional Emphasis

- **工业设计**: Emphasize technical decomposition, process evidence, material/prototype detail, mechanism diagrams, engineering views, and Proof of Concept close-ups.
- **交互设计/UX**: Emphasize the full path from topic -> research -> need -> concept -> prototype -> validation -> final presentation. Use user journeys, flows, service blueprints, UI states, testing, and iteration.
- **人机交互/HCI**: Emphasize system thinking, cross-disciplinary integration, technical feasibility, embodied/sensory interaction, research rigor, and academic visual tone.
- **服务/社会议题**: Emphasize layered evidence, data/persona/problem tree/service blueprint, and balance between empathy and academic restraint.
- **游戏/互动项目**: Emphasize mechanics, core loop, rules, onboarding, levels, interaction feedback, testing, engine/implementation evidence, and playable flow.
